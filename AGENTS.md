3. **Конвенция команд:** «исправьте» — немедленное устранение бага; «приступайте» — реализация обсуждённого функционала; без этих команд — только консультации.

## Экономия контекста и память проекта
* Основной расход токенов — входящий контекст: история перечитывается на каждом ходу. Проектная память хранится в файлах репозитория, не в диалоге.
* Постоянная память — `SESSION_STATE.md`: текущее состояние, открытые задачи, следующие шаги. Компактно, без воды; старые чекпоинты периодически сворачивать (последние 2–3 подробно, остальное строкой).
* Завершив логический этап, агент сам пишет «Checkpoint <дата>» в `SESSION_STATE.md` — с полнотой, достаточной для продолжения без перечитывания кода — и сообщает: «Этап завершён, рекомендую новый тред».
* Новая сессия начинается с чтения `SESSION_STATE.md` + `AGENTS.md`; старые файлы без нужды не перечитывать.
* Читать файлы точечно (grep/offset), длинные выводы фильтровать, отвечать по существу.

## Схема прибора при подключении
* `UpdateSondeScheme(true)` обновляет рисунок и подпись по `connectedSondeId` сразу после GET_SIGNATURE и после чтения метрологии, до первого GET_DATA. Обычный вызов использует подключённый прибор для живой сессии, а для открытого файла — его сигнатуру. `SondeSchemeControl::SetDeviceCaption` выводит тип и номер над схемой.
* В C++/CLI нельзя задавать аргументы по умолчанию методам управляемых классов (C3222); использовать перегрузки.

## Переключатели графиков
* DIRECT/UNDIRECT доступны только для типов 351/352; для GP (в том числе 349) оба графика принудительно UNDIRECT. В DIRECT у каждого графика независимая кнопка Rx L/R; выбор хранится как Receiver=0/1 в station_config.json. GetCurveValue принимает rxIdx, общий GEO SMT от L/R не зависит. Кривая Δφ VZX/VZZ использует ph_Vzx_Vzz в миллиградусах, не отношение амплитуд.
* StartDisplay переводит обе оси X на кадры, сбрасывает температурный zoom и скрывает переключатели оси; StopDisplay возвращает кнопки, оставляя ось кадров. У окна из одной точки Maximum должен быть больше Minimum.
* Смена кривой (чип/меню), DIRECT/UNDIRECT, Rx L/R и 400/2000 проходит через RefreshChart(windowIndex) → RenderChart(windowIndex). Обновляется только выбранный график; схема сразу привязывается к нему. При выключенном HoldZoom сбрасываются X/Y zoom и ручные границы, затем RecalculateAxesScale; при включённом сохраняется масштаб, как в старом do_chart. В потоке X всегда остаётся окном последних кадров.
* Кривые и закреплённые чипы запоминаются отдельно для DIRECT/UNDIRECT каждого графика (DirectActiveCurve/UndirectActiveCurve, DirectPinnedCurves/UndirectPinnedCurves в station_config.json). Допустимость кривых по режиму проверяется через `IsCurveValidForMode`: кривые чужого режима отбрасываются при загрузке и переключении. Закрытие всех чипов — пустой график; закрытие активной — предыдущая в списке. Старый конфиг без этих полей поддерживается.
* DIRECT: левая палитра Green/DarkGoldenrod/Red/RoyalBlue, правая DarkGoldenrod/Green/Red/RoyalBlue; одинаковые физические длины сохраняют цвет. Подписи Tx как в старой: L=T1/T2/T4/T5, R=T1/T2/T3/T5. Цвета серий и чекбоксов согласованы.
* После сборки соответствующей конфигурации: `python test_chart_controls.py --config Debug` / `--config Release`. Тест перелинковывает текущие obj (без main.obj) с временным C++/CLI entry point и C# reflection-проверками. Создаёт собственную форму вне экрана и временные настройки/данные; рабочие настройки не изменяются. Проверяются реальные значения L/R на графиках, сохранение выбора, AppendFrameToCharts, ось кадров в потоке и переход Картограф→GP→Картограф.
* Нельзя загружать основной mixed-mode EXE через Assembly.LoadFrom для UI-теста: CLR отклоняет native IAT/TLS (0x80131019). Использовать описанный отдельный entry point с obj из штатной сборки.

## Проверка GP-эмулятора
* `python test_em_probe.py` проверяет все GP-типы (231/242/349/151/152), размеры 240/320, сигнатуры GET_SIGNATURE/GET_DATA/GET_METROLOGY, нулевые отсутствующие Tx, HTTP-пульт и неизменность исходной модели. При наличии локальных `scripts/model_autonom_5Tx*.bin` они также проходят матрицу проверок; иначе этот тест явно пропускается. Все записи метрологии в тестах изолированы во временной папке.
* GP-файл-модель — исходный AUTONOM 5Tx 320 байт. Выбранные на пульте тип, номер и размер не заменяются параметрами модели. Массивы амплитудных УЭС и затуханий не входят в ответ 240 байт. Метрология GP всегда имеет размер 240 байт независимо от размера телеметрии; её выдаваемые сигнатура и номер соответствуют выбранному профилю.
* GP-эмулятор пересчитывает `phase_smt`, `att_dB_smt`, `rho_ph_smt`, `rho_att_smt` из сырых AM_RX_1/AM_RX_2/DELTA_PH по текущей метрологии на каждый GET_DATA. Изменение SET_METROLOGY применяется к следующему кадру; файл-модель не переписывается. Недопустимые результаты возвращаются нулевыми (в отличие от NaN наземного PC-расчёта). RAW-сектора Картографа остаются исходными.
* `test_pc_curves.py` дополнительно сравнивает пересчитанные эмулятором кадры с native `PcCurveValue`: все GP-типы, оба размера и обе частоты, исходная и изменённая метрология. Допуски: 0.01 мгр для фаз, 0.0001 дБ для затуханий, максимум 0.05 Ом·м или 0.5% для УЭС (Python complex против C++ complex<float>, пороги бисекции).

## Эмулятор Картографа
* BIN-модель хранит `DATA400 + DATA2000 + RAW400 + RAW2000` (3072 байта), даже когда сигнатура содержит 1536. GET_DATA возвращает поочерёдно DATA+RAW одной частоты (1536 байт), dds_freq=401/2001. DEV использует 11-байтовый префикс перед каждым частотным блоком; проверяются сигнатуры и порядок пар.
* Ненаправленные результаты пересчитываются из Rzz1/Rzz2 по общей части метрологии. Направленные Geo и SMT — из измеренных amp_Vzz/amp_Vzx/ph_Vzx_Vzz с beta/collar/фазовыми поправками по `CARTOGRAF_FIRMWARE/RHO_calc.c::calc_geo_signal_smt`. RAW-сектора, измеренные направленные параметры, INC/Wg и прочие независимые поля сохраняются.
* out_arr/all_bit_cntr пересобираются из новых данных по REAP_CONST/select_key: биты 24/25 включают частоты, младшие 24 — поля. Упаковка little-endian, младший бит первым; при двух частотах пакет размещается в блоке 2000. Некорректная конфигурация даёт пустую упаковку, не старые данные и не переполнение.
* Новая метрология при отсутствии файла: beta=45°, collar=0, фазовые поправки=0, REAP из прошивки. Существующие файлы не переписываются. Это нейтральные начальные коэффициенты, а не измеренная калибровка.
* `python test_em_probe.py` также проверяет Картограф, RAW-модель, DEV, смену метрологии, нулевые недопустимые результаты и select_key. `python test_pc_curves.py` сравнивает направленные результаты и упаковку с native-портом исходных функций прошивки. В harness учитывается 16-битный байт C2000 при переносе memset/memcpy/out_arr; исходники прошивки не изменяются.

## Эмулятор на Raspberry Pi 3B
* Pi 3B, RPi OS Trixie (cloud-init). Пользователь `user`/`1234`, SSH по паролю, sudo NOPASSWD. Точка доступа `emprobe-ap`: SSID `EMK-EMULEATOR`, **открытая**, канал 6, `ipv4.method shared` + `192.168.4.1/24` — как у реального прибора (WPA2 на brcmfmac нестабилен). Pi = `192.168.4.1`: станция → UDP 5000, пульт → `http://192.168.4.1:8080`, SSH/SCP — туда же. Ethernet — резерв.
* Автозапуск — `emprobe.service` (systemd, enabled): `python3 /home/user/emprobe/em_probe.py --bind 0.0.0.0 --port 5000 --http 8080 --sonde 352 --serial 5`, Restart=always. Логи: `journalctl -u emprobe`.
* Выбор пульта (тип/серия/размер GP/модель) сохраняется в `emprobe_config.json` рядом со скриптом и восстанавливается при старте поверх CLI-аргументов; файл в .gitignore.
* Развёртывание: cloud-init читает seed с bootfs только при `ds=nocloud;i=<id>` в `cmdline.txt` (ставит Raspberry Pi Imager при кастомизации); `firstrun.sh`/`systemd.run` ненадёжны. Файлы копировать через bootfs-папку `emprobe/` в `~/emprobe/`. Pi 3B — только 2.4 ГГц.

## Проверка кривых Sonde / PC
* `python test_pc_curves.py` компилирует временный native C++ harness через VS 2026 и сравнивает PC-УЭС с исходными `RO_ARG`/`RO_AMP` из соседнего `TEST_SONDE_KARTOGRAF_2.0/AIR_TEMP_1.0/variable.cpp`. Проверяет 3Tx/4Tx/5Tx, обе частоты, пределы диапазона, отсутствие метрологии, недопустимые амплитуды и неизменность исходных кадров/Sonde-полей.
* PC повторяет фактическую логику старого `simmetry`: маска condition принудительно обнулена, матрица единичная; применяются воздух и чередование знака. Это не реализация адаптивной симметризации по работоспособности Tx.
* Имена четырёх пар: `Δφ SMT Sonde/PC`, `RO Δφ Sonde/PC`, `ATT SMT Sonde/PC`, `RO ATT Sonde/PC`. Отсутствующая метрология даёт пустые точки PC и пояснение на оси; исходный CSV не пересчитывается. `ε RO` остаётся отложенной задачей.
